SmartCombo v0.1.0

一个输入框 + 一个下拉。零依赖、无构建，选中的是「值」，看见的是「标签」。

模式 A · 文本输入 + 下拉选择 mode: "select"

点进去就出全部候选，敲字即筛选；只能选清单里的值，敲了清单外的内容会在失焦时退回上一个有效值。提交的是代码，看见的是名字。

value: —

模式 B · 文本输入 + 下拉 + 新建选项 mode: "create"

清单里没有的标签直接敲进去，下拉里会多出一行「＋ 新建标签 “xxx”」，回车即成为新选项并留在清单里 —— 后面再打开就在候选之中了。

value: —

每行独立候选（联动表单）setOptions()

「部门」一变，「审批人」的候选跟着整体换掉 —— 每行一个实例、选项按行下发。这是筛选器、明细表、审批流里最常见的用法。

部门审批人切换后结果

异步候选源 options: (q) => Promise

候选来自接口时把 options 写成函数即可：打开下拉时带当前关键字请求，返回结果覆盖候选，期间显示「加载中…」，过期响应自动丢弃。

网络引入 jsDelivr

两条标签就够了 —— 不用 npm install，也不用构建。脚本挂在全局 SmartCombo 上，不需要 type="module"。生产环境把版本写死（@0.1.0）；@latest 只适合试玩。

<!-- 样式 + 脚本，就这两条 -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/smart-combo@0.1.0/smart-combo.css">
<script src="https://cdn.jsdelivr.net/npm/smart-combo@0.1.0/smart-combo.js"></script>

<script>
  new SmartCombo("#city", { options: ["北京", "上海", "深圳"] });
</script>

还没发到 npm 时，从 GitHub 取同一份文件即可（推完仓库就能用）： https://cdn.jsdelivr.net/gh/longavailable/smart-combo@v0.1.0/smart-combo.js。 可复制的最小页面见 examples/cdn.html。

最小用法

// 模式 A：只能选清单里的
new SmartCombo("#city", {
  options: [
    { value: "310000", label: "上海" },
    { value: "440300", label: "深圳" }
  ],
  mode: "select",
  placeholder: "选择城市",
  onChange: (value, item) => console.log(value)   // "310000"，不是 "上海"
});

// 模式 B：能选，也能新建
new SmartCombo("#tags", {
  options: ["前端", "后端", "设计"],
  mode: "create",
  name: "tag",                       // 随表单提交 value
  createLabel: "＋ 新建标签 “{value}”",
  onCreate: (text) => console.log("新建了", text)
});
